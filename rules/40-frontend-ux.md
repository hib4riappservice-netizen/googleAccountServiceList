## パフォーマンス

### PERF-01 Core Web Vitals の合格ライン

| 指標 | Google の good | 本プロジェクト | 判定方法 |
|---|---|---|---|
| **LCP** | ≤ 2.5s | **≤ 2.5s** | **MUST** — Lighthouse モバイル、3回実行の中央値 |
| **CLS** | ≤ 0.1 | **≤ 0.1** | **MUST** — 同上 |
| **INP** | ≤ 200ms | ≤ 200ms | **SHOULD** — 実測が取れるまで判定対象外（下記） |

Google は**実ユーザーデータの75パーセンタイル**で評価する。

**INP はラボ計測では算出できない**（実ユーザーの操作を必要とするため、Lighthouse では出ない）。
したがって実ユーザーが付くまで INP は合否判定に使えない。代替として **PERF-03 の初期JS量**を見る。
RUM / CrUX でフィールド値が取れるようになった時点で、INP を MUST に昇格させる。

> この表記は [01-definition-of-done.md](01-definition-of-done.md) G3 と一致させること。
> 一方だけ変更すると、同じ成果物で合否が反転する。

### PERF-02 既定で守る実装（MUST）

- 画像は `next/image`。**width/height または aspect-ratio を必ず指定**（CLS対策）
- ファーストビューの主要画像に `priority`
- フォントは `next/font` でセルフホスト（レイアウトシフトとサードパーティ接続の削減）
- `'use client'` を最小化する。**クライアントJSの量が INP に直結する**
- 独立したデータ取得は `Promise.all` で並列化（[10-architecture.md](10-architecture.md) ARC-07）
- 重い部分は `<Suspense>` で分割し、ページ全体を待たせない

### PERF-03 予算（SHOULD）

- 初期ロードのクライアントJS: **gzip後 200KB 以内**。超えたら、超えた理由を記録するか削る
- サードパーティスクリプトの本数は [20-security.md](20-security.md) **SEC-62（MUST・3本以内）に従う**
  （数値の規範はSEC-62 に一本化。ここで二重に定義しない）

## アクセシビリティ

**目標: WCAG 2.2 レベルAA。** WCAG 2.2 AA を満たせば JIS X 8341-3:2016 AA も満たす
（JISは WCAG 2.0 の一致規格で、2.2 は上位互換）。

日本では2024年4月から民間事業者にも**合理的配慮の提供が法的義務**となった。
アクセシビリティ確保そのものは努力義務だが、**後から直すコストが最も高い領域**である。

### A11Y-01 絶対に落とさない4つ（MUST）

修正コストが低く、壊れていると使えない人が出るもの。

1. **キーボードだけで主要導線を完走できる**
   Tabキーだけでサインアップ→主要アクション→ログアウトまで到達できること。
   フォーカスが見え、フォーカスが罠にはまらず（モーダルは除く。モーダルは意図的にトラップし、Escで閉じる）、順序が視覚順と一致する。
2. **フォーム項目に `<label>` が紐づいている**
   `htmlFor` / `id` の対応。プレースホルダはラベルの代わりにならない。
   エラーメッセージが `aria-describedby` で入力欄に関連づいている。
3. **意味のある画像に代替テキスト、装飾画像は `alt=""`**
   アイコンのみのボタンには `aria-label`。
4. **テキストのコントラスト比 4.5:1 以上**（18pt/14pt太字以上は 3:1）
   UIコンポーネント・グラフィックの境界は 3:1（1.4.11）。

### A11Y-02 WCAG 2.2 の新AA基準で踏みやすいもの（MUST）

- **2.4.11 Focus Not Obscured**: フォーカスされた要素が **sticky header やポップアップに完全に隠れない**。
  → sticky header がある場合は `scroll-margin-top` を設定する。
- **2.5.8 Target Size**: クリック/タップ対象は **24×24 CSSピクセル以上**（十分な間隔があれば例外）。
  → アイコンボタンのパディングに注意。
- **2.5.7 Dragging Movements**: ドラッグ操作には**ドラッグを使わない代替手段**を用意する。
  → 並べ替えUIには「上へ/下へ」ボタンを添える。
- **3.3.8 Accessible Authentication**: 認証に認知機能テスト（パズル、記憶）を必須としない。
  **パスワードマネージャの貼り付けを妨げない**。

### A11Y-03 App Router / SPA 固有（MUST）

デジタル庁のガイドブックが SPA の課題として挙げている領域。クライアント遷移で壊れやすい。

- ページ遷移後に **`<title>` が更新される**（`metadata` で設定）
- ページ遷移後に **フォーカスが適切な位置（主見出し等）へ移る**
- 動的に増える通知・エラーは **ライブリージョン**（`aria-live="polite"`、エラーは `assertive`）で伝える
- ルート要素に `lang="ja"`

### A11Y-04 マークアップ（MUST）

- 見出しは `h1` から順に。**見た目のためにレベルを飛ばさない**（サイズはCSSで）
- ランドマーク: `<header>` / `<nav>` / `<main>` / `<footer>`。`<main>` は1ページに1つ
- **`outline: none` でフォーカスリングを消さない**。消すなら同等以上の代替を必ず用意する
- クリックできるものは `<button>` / `<a>`。`<div onClick>` にしない
  （`<a>` は遷移、`<button>` は操作。用途で使い分ける）
- ネイティブ要素で足りるなら ARIA を使わない。**間違ったARIAは、ARIAなしより悪い**

### A11Y-05 検証方法（MUST）

- **MUST** 開発中: `eslint-plugin-jsx-a11y` を有効化し、警告0
- **MUST** リリース前: Lighthouse Accessibility スコア **90以上**
- **MUST** 新規/変更画面ごとに **Tabキーで一周する**（自動検出できない問題の大半はこれで見つかる）
- **SHOULD** axe DevTools または `@axe-core/playwright` を E2E に組み込む
- 自動チェックはWCAGの問題の一部しか検出できない。**手動のキーボード確認を省略しない**

## UX

### UX-01 4つの状態（MUST）

データを扱うすべてのUIに以下を実装する。1つでも欠けたら未完成。

| 状態 | 要件 |
|---|---|
| **loading** | スケルトンまたはスピナー。**レイアウトが跳ねない**（CLS対策と兼ねる） |
| **success** | 通常表示 |
| **empty** | 「まだありません」＋**次の行動への導線**。空白のまま放置しない |
| **error** | 何が起きたか＋**再試行手段**＋（想定外なら）エラーID |

### UX-02 フォーム（MUST）

- 送信中はボタンを無効化する（二重送信防止）。
  **サーバー側の冪等性は [20-security.md](20-security.md) SEC-84 に従う**（規範はそちらに一本化）
- バリデーションエラーは **該当フィールドの近く**に、何をすればよいかが分かる文言で表示
- 入力内容が失われない（エラー時に再入力させない ── WCAG 2.2 の 3.3.7 Redundant Entry）
- **確認ダイアログは不可逆な操作（削除・解約・送金）にのみ置く**。それ以外には置かない
- 成功したことが分かる（トースト、遷移、内容の更新）

### UX-03 レスポンシブ（MUST）

- **375px 幅で崩れない**（最低ライン）
- 横スクロールが発生しない
- タップ対象は 24×24px 以上（A11Y-02）、実用上は 44×44px を推奨

### UX-04 文言（SHOULD）

- エラー文言は「何が起きたか」+「どうすればよいか」。**「エラーが発生しました」だけにしない**
- 技術用語をユーザーに見せない（"500 Internal Server Error" をそのまま出さない）
- 日本語のUIでは、ボタンラベルを動詞で終える（「保存する」「削除する」）など、
  プロジェクト内で表記を統一する。統一ルールは `docs/writing.md` に置く
