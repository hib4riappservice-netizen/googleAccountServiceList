# 50. 日本の法令対応

根拠: [sources/07-japan-legal.md](sources/07-japan-legal.md) /
[sources/08-japan-accessibility.md](sources/08-japan-accessibility.md)

> **免責**: 本ファイルは調査時点（2026-08-11）の要約であり法的助言ではない。
> 課金・個人情報・広告が絡む機能は、実装前に一次条文と所管官庁のガイドラインを確認すること。
>
> **前提**: 「個人開発だから適用されない」ということはない。
> 特定商取引法・個人情報保護法は、法人／個人を問わず、営利目的でサービスを提供する事業者に適用される。

## JP-00 判定フロー（まずこれで自分の必要範囲を決める）

```
メールアドレス等の個人情報を取得する？
  └ Yes → プライバシーポリシー【必須】＋ 安全管理措置【必須】

Google Analytics / 広告タグ / SNSピクセル等を入れる？
  └ Yes → 外部送信に関する公表【必須】

課金する（サブスク・買い切り・EC）？
  └ Yes → 特定商取引法に基づく表記【必須】＋ 申込み確認画面の要件【必須】
  └ 広告収益のみ → 特商法表記は原則不要

ユーザー投稿を扱う？
  └ Yes → 通報・削除依頼の窓口【必須】＋ 利用規約の禁止事項【必須】

18歳未満が使いうる？
  └ Yes → 2026年改正で子どもの個人データ規律が強化される方向。設計時点で扱いを決める
```

## JP-01 掲示ページ（MUST・G3リリースゲート）

**フッターにリンクを置く**のが標準。ログイン前後どちらからもアクセスできること。

| ページ | 必要条件 | 中身の要点 |
|---|---|---|
| **プライバシーポリシー** | 個人情報を取得するなら常に | 取得する情報、利用目的、第三者提供、委託、保管期間、開示等請求の窓口、安全管理措置 |
| **外部送信に関する公表事項** | 解析・広告タグを使うなら | 送信される情報、**送信先の事業者名**、送信先での利用目的。PP内の節でも可 |
| **利用規約** | 実務上ほぼ常に | サービス内容、禁止事項、アカウント停止条件、免責、準拠法・管轄、規約変更手続き |
| **特定商取引法に基づく表記** | **有料課金があるなら必須** | 事業者名（氏名）、住所、電話番号、価格、追加費用、支払方法と時期、提供時期、返品・解約 |
| **お問い合わせ窓口** | 常に | 開示請求・削除依頼・障害報告の受け皿。フォームまたはメールアドレス |

- **MUST** これらは**公開の条件**であり、公開後のTODOではない。
- **MUST** テンプレートを使う場合も、**実際のサービスの実態に合わせて書き換える**
  （取得していない情報を書く／取得している情報を書かない、はどちらも問題）。

## JP-02 個人情報の扱い（MUST）

- **MUST** 収集する個人情報を**列挙できる**（何を、なぜ、どこに保存し、いつ消すか）。
- **MUST** **利用目的の範囲外に使わない**。PPに書いていない用途に使わない。
- **MUST** 安全管理措置: 保存時の暗号化、アクセス制御、アクセスログ、
  クラウド（委託先）の選定と監督。
- **MUST** **ユーザーが自分でアカウントを削除できる導線がある**。方針を決めるだけでは不足で、
  **実際に動く削除機能**が必要。削除実行時に「消すデータ／残すデータ（会計上の保存義務があるもの等）」と
  **バックアップ内データの取り扱い**（保持期間の経過で消える旨）を `docs/privacy-ops.md` に書き、
  プライバシーポリシーの記載と一致させる。
  → バックアップは [60-delivery-ops.md](60-delivery-ops.md) OPS-01 で必須なので、
    **「削除したはずのデータがバックアップに残る」問題は必ず発生する**。先に扱いを決めておく。
- **MUST** **開示・訂正・利用停止・消去の請求を処理する手順**が `docs/runbook.md` にある。
  窓口（フォーム）を置くだけでは不足。請求が来てから手順を考えると対応期限に間に合わない。
- **MUST** 目的を達したデータを保持し続けない。保持期間を決め、超過分を消す手段がある。
- **MUST** 要配慮個人情報（健康、信条、犯罪歴等）は**原則として取得しない**。
  必要なら原則として本人同意が必要で、要件が厳しい。
- **MUST** 漏えい時の対応手順を用意しておく（一定の漏えいは**個人情報保護委員会への報告と本人通知が義務**）。
  → [checklists/release.md](checklists/release.md) 参照。
- **SHOULD** そもそも**取らない**ことを最初に検討する。持たない個人情報は漏れない。

### 2026年改正への備え（SHOULD）

2026年7月17日公布。施行は公布から2年以内（罰則等一部は約6か月後）。

- **課徴金制度が初めて導入**され、個人情報保護委員会の執行権限が拡大する。
- 方向性は「書面が整っていること」ではなく **日常の運用実態と証跡** が問われること。
- **子どもの個人データ・顔特徴データ・連絡先情報**の規律が強化される。
  → 顔写真の特徴量、年齢確認、連絡先の同期などを扱う機能は、設計段階で慎重に判断する。

## JP-03 外部送信規律（電気通信事業法）（MUST）

2023年6月16日施行。**個人情報に該当しない情報も対象**である点に注意。

### 対象になるもの

Cookieに保存されたID、広告ID等の識別符号、利用者の行動に関する情報を**外部（第三者）へ送信させる**とき。
Google Analytics、Google Ads、Meta Pixel、外部埋め込み、外部CDN上のスクリプト等が典型。

### 対応（いずれか1つ。通常は「公表」）

1. **所定事項の通知または公表** ← 個人開発ではこれが現実的
2. 同意の取得
3. オプトアウトの措置

「公表」= **容易に知り得る状態に置く**こと。フッター等から容易にアクセスできる場所に、
**送信される情報／送信先の事業者名／送信先での利用目的**を記載した文書を置く。

### 適用除外

- サービスの利用に**必須**な情報（セッション維持等）
- 利用者識別のために**自社に**送信させる識別符号（1st party Cookie のID）

### 実装ルール

- **MUST** 解析タグ・広告タグを追加したら、**同じPRで公表事項を更新する**。
  タグの追加と表記の更新を別作業にしない（必ず忘れる）。
- **SHOULD** サードパーティタグの一覧を `docs/third-party.md` に持ち、公表事項と対応づける。

## JP-04 課金する場合（MUST）

- **MUST** **自分で資金を預からない**。Stripe 等の決済代行（PSP）を使う。
  自前で資金を保有・移転すると**資金決済法**の規制対象になりうる。
- **MUST** ポイント・プリペイド・チャージ機能は **前払式支払手段**に該当しうる。安易に作らない。
- **MUST** 決済の成否を**クライアントの申告で判断しない**。Webhook の署名を検証してサーバーで確定する
  （[20-security.md](20-security.md) SEC-60/61）。
- **MUST** カード番号を自分のサーバーで受けない（Stripe Elements / Checkout 等でPSPに直接渡す）。
- **MUST** **申込み最終確認画面**で、金額・支払時期・自動更新の有無・解約方法を明示する（特商法）。
- **MUST** **解約導線が次の3条件をすべて満たす**（「分かりやすく」を判定可能にしたもの）。
  解約を不当に困難にするUIはダークパターンとして問題になる。
  1. ログイン後の画面から **2クリック以内**で解約画面に到達できる
  2. 申込み導線と**同じ階層**（設定 or アカウント画面）にある
  3. テキストリンクではなく**ボタン**として存在する
  - E2E テストで「ログイン → 解約画面到達」を1本置く。
- **MUST** 特商法表記に、氏名・住所・電話番号を含む所定事項を記載する。
  （個人開発者の住所開示が問題になる場合は、条件を確認したうえで対応方法を決める）

## JP-05 ユーザー投稿・広告表示がある場合（MUST）

- **MUST** 通報・削除依頼の窓口を用意する（プロバイダ責任制限法／情報流通プラットフォーム対処法）。
- **MUST** 利用規約に禁止事項と削除・アカウント停止の条件を明記する。
- **MUST** アフィリエイトリンク・PR記事・レビュー掲載がある場合、
  **事業者の広告であることを明示する**（景品表示法のステマ規制、2023年10月施行）。
- **MUST** サクラレビュー・自作自演のレビューを掲載しない。
- **MUST** 抽選・プレゼント企画は景品規制（景品類の上限額）を確認する。

## JP-06 アクセシビリティの法的位置づけ（MUST）

- 2024年4月1日から、**民間事業者にも「合理的配慮の提供」が法的義務**（障害者差別解消法）。
- ウェブアクセシビリティ（JIS準拠）そのものは民間には義務付けられておらず、**環境の整備（努力義務）**。
- **本プロジェクトの方針**: WCAG 2.2 レベルAA を目標とし、
  [40-frontend-ux.md](40-frontend-ux.md) A11Y-01 の4項目は**MUSTとして落とさない**。

## JP-07 やらないと決めること（MUST）

個人開発で踏み込むと規制・責任が重くなる領域。**明示的に「やらない」と決め、規約に書く**。

- 医療・健康アドバイス（薬機法、医師法）
- 投資・金融の助言（金商法）
- 法律相談（弁護士法）
- 送金・資金の預かり（資金決済法）
- 人材紹介・職業紹介（職安法）
- 出会い系（異性紹介事業の届出）

これらに近い機能を作りたくなったら、**実装前に立ち止まる**。
