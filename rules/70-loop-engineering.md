# 70. ループエンジニアリング

根拠: [sources/10-loop-engineering.md](sources/10-loop-engineering.md)

---

## なぜこのファイルが必要か

`00-principles.md` P6 が示すラダー（型 → lint → テスト → CI → チェックリスト）は、
**人間が確認する前提のゲート**を機械化する話だった。ループエンジニアリングは一段別の話で、
**エージェントを無人で何周も走らせる**ときに何が要るかを定める。

順序を間違えると事故になる。**ハーネス（`pnpm verify` が緑/赤を返せること、git、CI）が
先に存在しない状態でループだけを作らない。** ループはハーネスの上に乗る制御方式であって、
ハーネスの代わりにはならない（[sources/10-loop-engineering.md](sources/10-loop-engineering.md)）。

---

## ループの4要素

| 要素 | 本ルール群での担保 |
|---|---|
| 明確なタスク | [01-definition-of-done.md](01-definition-of-done.md) G0（1文・Given/When/Then・停止条件） |
| 安全な作業場 | LOOP-02（worktree）。ブランチ運用は [60-delivery-ops.md](60-delivery-ops.md) DEV-01 |
| 本物の成功テスト | `pnpm verify`（[30-testing.md](30-testing.md) TEST-07）。LLMの主観判定は単独の停止条件にしない |
| ハードストップ | LOOP-01（turn上限・no-progress条件） |

---

## LOOP-01 上限を設定する（MUST）

すべてのループに **turn上限** を設定する。初期値は **5**
（Anthropic の `/goal` 使用例に準じた本プロジェクトの判断。公式の既定値ではない ──
[sources/10-loop-engineering.md](sources/10-loop-engineering.md)）。タスクの性質に応じて調整してよいが、
**上限を設定しないループを走らせない**。

- **MUST** 同一の失敗（同じテストが同じ理由で赤）が **2回連続**したら停止し、人間に戻す
  （`sources/09-agentic-coding.md` の「2回で `/clear`」を数値規範に昇格したもの）。
- **MUST** turn上限に達したら、そこまでの証拠（実行したコマンドと結果）とともに停止する。
  「もう少しで終わる」を理由に上限を超えない。

## LOOP-02 隔離された作業場で実行する（MUST）

無人で走らせるループは **git worktree** 上で行う。作業ディレクトリが独立するため、
ループが暴走しても被害はその worktree 内に閉じる。

- **MUST** 本番DB・`.env*`・適用済みマイグレーション・デプロイ操作は、
  ループの通常フローに含めない（`CLAUDE.md`「触ってはいけないもの」節をループの割り込み条件として扱う）。
  これらに触れる必要が生じたら停止し、人間の判断を仰ぐ。

## LOOP-03 停止条件の判定は実装者と分離する（MUST）

ループの停止条件（緑/赤）を、そのループ自身が実装したコードに対して**そのループ自身が主観で判定しない**。

- **MUST** 停止条件は `pnpm verify` のような機械的コマンドの終了コードで判定する。
- **SHOULD** 機械判定できない項目の最終確認には、独立したコンテキストのサブエージェント
  （`sources/09-agentic-coding.md` の敵対的レビュー）を使う。
- **MUST** LLMの「完了しました」という自己申告だけを根拠に、ループを止めた（＝合格とみなした）と
  報告しない。証拠（実行したコマンドと出力）を示す。
- **MUST** turnごとの証拠を、後から検証できる形で残す。**1コミットに圧縮しない。**
  turnごとにコミットを分けるか、turnの実行ログ（コマンド・終了コード・出力）を
  ファイルとして残す。散文の要約だけでは、赤だった事実も緑になった過程も検証できない
  （2026-08-13追記: 最初のループ実行はコミットメッセージの散文のみを根拠にしており、
  この MUST 自体に違反していた。監査 loop-auditor-2 指摘D-2）。

## LOOP-04 検証（Verdict）は人間が持つ（MUST）

ループが緑を返しても、それは**実行の証拠**であって承認そのものではない
（[sources/10-loop-engineering.md](sources/10-loop-engineering.md)「Own the Outer Loop」）。

- **MUST** G0（何を作るか）の合意は人間が行う。ループの外に置く。
- **MUST** `checklists/human.md` に分離された項目（機械判定できないもの）は、
  ループの完了をもって「満たされた」とみなさない。人間が別途確認する。
- **MUST** ここで人間が持つ「検証」は**最終承認**であり、技術的な合否判定を人間に
  振ることではない（[00-principles.md](00-principles.md) P9）。技術的な合否は
  `pnpm verify` とレビュー3体で決着させ、Critical/High の指摘を解消してから人間に見せる。

## LOOP-05 ループに載せてはいけないタスク（MUST）

以下は停止条件を機械的に書けない、または不可逆であるため、ループの外で人間が行う。

- 本番の不可逆操作（本番DBへの書き込み、デプロイ、アカウント削除の実行確認）
- 法的判断（プライバシーポリシーと実態の一致、要配慮個人情報の要否）
- リストア手順の実地試行
- 「何を作るか」という製品・事業判断そのもの
  （技術的な「どう作るか」の判断はループの外でも人間に振らない。[00-principles.md](00-principles.md) P9）

## 最小のループの例

停止条件が完全に決定的なものから始める。

```
題材: G0 の Given/When/Then をテスト名に落とし、赤 → 緑にする
作業場: git worktree
turn単位の停止条件: 対象ファイルに絞った `pnpm test <file>` の終了コードが 0
マージ前ゲート: `pnpm verify:full`（CI）が緑（[30-testing.md](30-testing.md) TEST-07）
turn上限: 5
no-progress条件: 同一テストが2回連続で赤なら停止
```

この1本が完走するまで、他のループを増やさない。
