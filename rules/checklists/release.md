# チェックリスト: リリース前（G3）

**初回公開時は全項目**、以降のリリースでは**変更が触れた項目**を通す。

各項目の末尾は出典ID。
**[01-definition-of-done.md](../01-definition-of-done.md) G3 の MUST は、漏れなくこのリストに現れること。**
逆は不要 ── このリストにしかない項目（SEC-05、SEC-42、SEC-60 等）は出典IDで規則本体に紐づいていればよい。
DoD の MUST を変更したら、同じPRでこのリストも更新すること（[README.md](../README.md) メンテナンス節）。

無印は MUST。SHOULD の項目には明示的に `(SHOULD)` と書く。

判定手段タグは [checklists/feature.md](feature.md) と同じ規約。
`[人間]` に該当する項目は [checklists/human.md](human.md) にも集約してある。

## セキュリティ — 本番設定（A02）

`pnpm check:headers <URL>` で SEC-90/92/98 を機械判定する（`scripts/check-headers.mjs`。
`URL` を省略すると `http://localhost:3000`）。CIの`headers`ジョブが`localhost`に対して
自動実行する（HSTS系はSKIP）。**HSTS等の本番限定項目は、本番/ステージングURLに対して
手動で一度は実行すること**（`http://localhost` に対する実行では代替しない）。

- [ ] `NODE_ENV=production`、デバッグ / 詳細エラー表示が無効〔SEC-90〕 `[自動]`
- [ ] HTTPS 強制、HSTS 有効〔SEC-91〕 `[自動]`（要 https ターゲット。localhostではSKIP表示になる）
- [ ] `Content-Security-Policy` 設定済み（`unsafe-eval`・ワイルドカードを含まない）〔SEC-92〕 `[自動]`
      （`unsafe-inline` は `docs/decisions.md` 記載の許容例外。SEC-64のStripe.js例外と同様の扱い。
      `script-src`未指定時は`default-src`にフォールバックする判定に修正済み）
- [ ] `Strict-Transport-Security: max-age=63072000; includeSubDomains`〔SEC-92〕 `[自動]`（要 https ターゲット）
- [ ] `X-Content-Type-Options: nosniff`〔SEC-92〕 `[自動]`
- [ ] `Referrer-Policy: strict-origin-when-cross-origin`〔SEC-92〕 `[自動]`
- [ ] `frame-ancestors 'none'`（または `X-Frame-Options: DENY`）〔SEC-92〕 `[自動]`
- [ ] **`Permissions-Policy`**（使わない機能を無効化）〔SEC-92〕 `[自動]`
- [ ] CORS が `*` でない〔SEC-93〕 `[要自動化]`（CORSを返すエンドポイントが無いため未実装。API追加時に対応する）
- [ ] 認証Cookieが `HttpOnly` + `Secure` + `SameSite=Lax`〔SEC-94〕 `[要自動化]`（`Set-Cookie` ヘッダの検査で可能。認証実装後）
- [ ] 本番DBの接続ユーザーが最小権限（DDL権限を持たない）〔SEC-95〕 `[人間]`（インフラ側の設定確認）
- [ ] ストレージの公開バケットに非公開ファイルがない〔SEC-96〕 `[人間]`
- [ ] 管理画面 / シードデータ / テストアカウントが本番に存在しない〔SEC-97〕 `[人間]`
- [ ] `/.env`、`/.git`、ソースマップが公開されていない〔SEC-98〕 `[自動]`（`/.env`・`/.git/*` を検査。ソースマップは未実装）
