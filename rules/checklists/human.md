# チェックリスト: 人間確認のみ（G2 + G3/G4 横断）

[checklists/feature.md](feature.md) と [checklists/release.md](release.md) から
`[人間]` タグの項目だけを**機械的に抽出**したもの（原本はそちら。ここは集約表示）。

**このリストは判定の正本ではない。** MUST/SHOULDの割り当てや出典IDは元ファイルを見る。
リリースのたびに132項目すべてを1人で通すのは非現実的なので、
**機械判定できる項目（`[自動]` `[要自動化]`）が全て緑になった後、ここだけをまとめて通す**運用にする。

[70-loop-engineering.md](../70-loop-engineering.md) LOOP-04 の通り、
無人ループが緑を返しても、ここに載る項目の充足を代替しない。

## G2（機能完成時）— feature.md より

### 0. 前提
- [ ] デバッグコード・コメントアウトされた死んだコードを残していない

### 1. 仕様
- [ ] G0 で定義した Given / When / Then がすべて満たされている
- [ ] 満たせなかった条件がある場合、**明示して記録した**（黙って落としていない）

### 2. 型
- [ ] 外部入力（フォーム / `searchParams` / `params` / ヘッダ / 外部API）が**境界でスキーマ検証**を通っている
- [ ] 状態が判別可能なunionで表現され、**ありえない組み合わせが型として作れない**

### 3. 権限（最重要）
- [ ] データの読み書きが **`server-only` な DAL 関数**を経由している
- [ ] DAL 関数の中で**認証**（誰か）を確認している
- [ ] DAL 関数の中で**認可**（このリソースの所有者か / 権限があるか）を確認している
- [ ] Server Action がページの `redirect()` に依存せず、**アクション経由でも認可が効く**
- [ ] クライアントに返るのが **DTO**（UIに必要なフィールドのみ）で、DBレコードそのままでない
- [ ] Client Component の props 型が広すぎない（`user: User` のようになっていない）
- [ ] Server Action の**戻り値**が最小限

### 4. テスト
- [ ] 純粋なビジネスロジックにユニットテストがある
- [ ] DAL / Server Action / Route Handler に統合テストがある
- [ ] **「他人のリソースを操作しようとすると失敗する」テスト**がある
- [ ] バリデーションの境界値・不正入力のテストがある
- [ ] （バグ修正なら）修正前に失敗する回帰テストを**先に**書いた
- [ ] クリティカルパスを変えたなら E2E を追加/更新した

### 5. 壊れ方
- [ ] empty の表示があり、**次の行動への導線**がある
- [ ] error の表示に3要素がある: ①何が起きたか ②次に取れる操作 ③（想定外なら）エラーID
- [ ] 認可・検証の失敗が「拒否」に倒れている（フォールバックで通していない）
- [ ] 外部API呼び出しにタイムアウトがある
- [ ] **決済・課金確定・メール送信・Webhook受信に冪等キーがあり、二重実行テストがある**（SEC-84）

### 6. 観測
- [ ] 未捕捉例外がエラー監視に届く
- [ ] 重要な操作（作成 / 更新 / 削除 / 課金 / 認証）が構造化ログに残る
- [ ] ログとエラー監視に **パスワード / トークン / APIキー / 個人情報の本文が入っていない**

### 7. 戻せる
- [ ] 1コミット or 1PRで revert できる
- [ ] DBマイグレーションがあるなら**後方互換**（旧コードでも動く）

### UIを変更した場合
- [ ] **Tabキーだけで一周した**（フォーカスが見える / 順序が視覚順と一致 / 罠にはまらない）
- [ ] sticky header にフォーカスが隠れない
- [ ] ドラッグ操作があるなら**ドラッグ以外の代替手段**がある
- [ ] 確認ダイアログを置いたのは不可逆な操作（削除・解約・送金）のみ
- [ ] （クライアント遷移があるなら）遷移後に `<title>` が更新され、フォーカスが移る

### デザイン（見た目）を変更した場合
- [ ] ヘッダー・フッター等の固定要素が、動的なコンテンツ量に関わらず画面内に留まる
- [ ] 配色に明確な役割分担がある（主要操作・副次操作・外部サービス連携ボタン等が同じ色で塗られていない）
- [ ] アイコンを使うなら実在するアイコンセットから取得し、機能を補強する箇所にのみ絞って使う
- [ ] 他社サービス連携ボタンは、そのサービスのブランドガイドラインに沿った配色・ロゴを使う
- [ ] 説明文・注意書き・警告文が種類ごとに分離されている
- [ ] 常時参照する必要のない説明文は折りたたみ式にする等、初見の情報量を絞っている
- [ ] 見出し・タグライン等の短いテキストが、想定ビューポート幅で不自然に折り返さない
- [ ] 機能的な意味を持たない装飾要素を追加していない
- [ ] 実装後、実際にブラウザで（スクリーンショット等で）見た目を確認した

### 外部サービス/依存/タグを追加した場合
- [ ] 最終公開日が12か月以上前、または週間DL数が1万未満なら、採用理由を書いた（SEC-12）
- [ ] 10行で書けるものに依存を足していない

### 個人情報を新たに扱う場合
- [ ] 何を / なぜ / どこに保存し / いつ消すか を説明できる
- [ ] **プライバシーポリシーの記載と実態が一致している**（同じPRで更新した）
- [ ] **アカウント削除時にこのデータがどうなるか**が決まっており、`docs/privacy-ops.md` に書いた（JP-02）
- [ ] 保存時の暗号化・アクセス制御がある
- [ ] 要配慮個人情報を取得していない
- [ ] (SHOULD) そもそも取らずに済ませられないか検討し、その結論を書いた〔JP-02〕

## G3/G4（リリース前後）— release.md より

### 品質
- [ ] (SHOULD) INP ≤ 200ms。**ラボでは測れないため実測が取れるまで判定対象外**〔PERF-01〕

### セキュリティ — 本番設定
- [ ] 本番DBの接続ユーザーが最小権限（DDL権限を持たない）〔SEC-95〕
- [ ] ストレージの公開バケットに非公開ファイルがない〔SEC-96〕
- [ ] 管理画面 / シードデータ / テストアカウントが本番に存在しない〔SEC-97〕

### セキュリティ — シークレット
- [ ] 過去に漏れたシークレットは rotate 済み〔SEC-102〕

### セキュリティ — 依存
- [ ] 追加した依存について、PR本文に 週間DL数 / 最終公開日 / 直接依存数 を記載した〔SEC-12〕

### セキュリティ — アプリケーション
- [ ] 認可のテストが主要エンドポイントに存在する〔SEC-05〕
- [ ] 書き込み系エンドポイントにサイズ上限・件数上限がある〔SEC-40〕
- [ ] ファイルアップロードがあるなら、MIME検証・サイズ上限・別ドメイン配信〔SEC-42〕
- [ ] Webhook の署名検証が有効（Stripe等）〔SEC-60〕
- [ ] **決済・課金確定・メール送信・Webhook受信に冪等キーがあり、二重実行テストが通る**〔SEC-84〕
- [ ] 決済の成否をサーバー側で確定している（クライアントの申告で判断していない）〔SEC-61〕

### 法令・表記（日本）
- [ ] **プライバシーポリシー**が公開され、フッターからアクセスできる〔JP-01〕
- [ ] PPの記載内容が**実際に取得している情報と一致**している〔JP-01〕
- [ ] （解析/広告タグを使うなら）**外部送信に関する公表事項**が掲示されている〔JP-03〕
- [ ] 公表事項に「送信される情報 / 送信先の事業者名 / 送信先での利用目的」が書かれている〔JP-03〕
- [ ] **利用規約**が公開されている〔JP-01〕
- [ ] **お問い合わせ窓口**がある〔JP-01〕
- [ ] **アカウント削除導線が存在し、実際に動作する**（本番で1回実行して確認）〔JP-02〕
- [ ] 削除時に消すデータ／残すデータとバックアップ内の扱いが `docs/privacy-ops.md` にあり、PPと一致〔JP-02〕
- [ ] **開示・訂正・利用停止請求の処理手順**が `docs/runbook.md` にある〔JP-02〕
- [ ] （有料課金があるなら）**特定商取引法に基づく表記**がある〔JP-01, JP-04〕
- [ ] （有料課金があるなら）申込み最終確認画面に金額・自動更新・解約方法が明示されている〔JP-04〕
- [ ] （UGCがあるなら）通報・削除依頼の窓口がある〔JP-05〕
- [ ] （広告・アフィリエイトがあるなら）広告であることを明示している〔JP-05〕

### 運用
- [ ] エラー監視が本番で有効、**テストイベントを飛ばして通知先が生きていることを確認した**〔OPS-01〕
- [ ] DBバックアップが有効〔OPS-01〕
- [ ] **リストア手順を1度は実際に試した**〔OPS-01〕
- [ ] ロールバック手順が `docs/runbook.md` に書かれている〔DEV-05〕
- [ ] (SHOULD) アップタイム監視がある〔OPS-01〕
- [ ] (SHOULD) リリース後に対応できる時間帯である。難しいなら feature flag OFF で出す〔DEV-05〕

### リリース後（G4）
- [ ] 本番でクリティカルパスを**手で1回通した**（スモークテスト）〔G4〕
- [ ] (SHOULD) 主要指標（登録、主要アクションの成功率）が想定内〔G4〕
