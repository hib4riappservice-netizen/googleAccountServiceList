# OWASP Top 10:2025

出典: https://owasp.org/Top10/2025/ / https://owasp.org/www-project-top-ten/

## カテゴリ一覧（2025年版）

| ID | カテゴリ | 個人開発Webアプリでの主な現れ方 |
|---|---|---|
| A01 | Broken Access Control | 他人のIDを指定すると他人のデータが取れる（IDOR）。2021版のSSRFはここに統合 |
| A02 | Security Misconfiguration | 本番でデバッグ有効、デフォルト認証情報、CORS全許可、公開バケット |
| A03 | Software Supply Chain Failures | **新設**。依存パッケージ、ビルド、CI/CD、サードパーティSaaSまで含む |
| A04 | Cryptographic Failures | 平文パスワード、弱いハッシュ、HTTP混在、秘密のハードコード |
| A05 | Injection | SQLi / XSS / コマンドインジェクション |
| A06 | Insecure Design | そもそも設計に脅威モデルがない。レート制限・上限の欠如 |
| A07 | Authentication Failures | 総当たり可能、セッション固定、パスワードリセットの穴 |
| A08 | Software or Data Integrity Failures | 署名検証なしの更新、安全でないデシリアライズ |
| A09 | Security Logging and Alerting Failures | 攻撃・障害に気づけない。監査ログがない |
| A10 | Mishandling of Exceptional Conditions | **新設**。例外時に安全でないフォールバック、エラーからの情報漏洩 |

## 2021版からの主な変化と、そこから読める「今の重心」

- **Security Misconfiguration が #5 → #2 に上昇**：コードの脆弱性より「設定」が事故の主因になっている。
- **Software Supply Chain Failures を新設（#3）**：自分が書いたコードだけを守っても足りない。依存・CI・ビルドが攻撃面。
- **Mishandling of Exceptional Conditions を新設（#10）**：「壊れ方」が独立した品質項目になった。失敗時に安全側に倒れるかを設計対象とする。
- 全体として、個別のコーディング欠陥から **エコシステム全体・ライフサイクル全体の防御** へ焦点が移っている。
