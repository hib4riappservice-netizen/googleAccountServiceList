# 個人情報の運用（JP-02）

`rules/50-japan-compliance.md` JP-02に基づく。アカウント削除時にデータがどうなるかを明確にする。

## 現状（Googleサインインのみ）

本サービスはデータベースを持たない。Googleサインインで取得する氏名・メールアドレス・
プロフィール画像は、Auth.jsの暗号化JWTセッション（HttpOnlyのブラウザCookie）にのみ存在する。

- **削除の実行方法**: サインアウトすると即座に消える（Cookieが失効する）。
  加えてセッション自体も一定期間で自動失効する。
- **バックアップへの残留**: 発生しない。DBを持たないため、DBのバックアップという概念自体がない。
- **本サービス側からGoogleへのアクセス権を取り消す方法**: 利用者は
  [Googleアカウントのアプリ許可設定](https://myaccount.google.com/permissions) から、
  本サービスへのアクセス権自体をいつでも取り消せる。取り消すと次回以降サインインできなくなる。
- **「アカウント削除」導線を別途用意していない理由**: 本サービス側にサーバー保存された
  アカウント/データが存在しないため、削除すべき対象がない。サインアウト＋Google側の
  アプリ許可取り消しで実質的に完了する。

## Gmail走査機能（2026-08-15追記）

「登録済みサービス検出」機能は、Gmailのメッセージヘッダー（件名・送信元アドレス・受信日時。
**本文は取得しない**）を`gmail.readonly`権限で読み取る。

- **保存**: 一切しない。スキャンのリクエスト処理中のみメモリ上に存在し、レスポンスとして
  画面に返した時点で消える。DB・ログ・セッションのいずれにも書き込まない
  （エラー時のログにはエラーIDのみを残し、メール内容は残さない）。
- **削除**: 保存していないため、削除すべき対象が無い（サインインのみの場合と同じ扱い）。
- **見直し条件**: 何らかのデータをサーバー側に保存する機能を追加したら、このファイルを
  更新し、保存する情報ごとに削除方法・バックアップの扱いを追記する。

## エラー監視（Sentry、2026-08-16追記）

未捕捉例外の検知のために、エラーメッセージ・スタックトレース・発生したURL・環境名を
第三者サービス（Sentry、米国法人）へ送信する。

- **個人情報は送信しない**: `dataCollection: { cookies: false, httpHeaders: false }`
  を明示指定し、CookieとHTTPヘッダーを構造的に除外している（`sendDefaultPii`の既定値
  だけに頼ると名前ベースの一部除外にとどまるため、明示指定に変更した）。IPアドレスも
  収集しない。`Sentry.setUser()`も呼んでいないため、利用者を識別する情報
  （メールアドレス等）は付与されない。公開ページ側は`app/privacy/page.tsx`の
  「第三者提供」に記載。
- **Gmail走査機能のメール内容は対象外**: `data/gmail.ts`のエラーログはエラーIDのみを
  記録する設計（上記「Gmail走査機能」節参照）で、Sentryへの送信もこの設計を継承する。
  メールの件名・送信元・本文がSentryに渡ることはない。
- **保存期間**: Sentry Developerプラン既定のリテンション（90日）に従う。本サービス側で
  個別に削除する手段は用意していない（個人情報を含まないため）。
- **見直し条件**: 将来`Sentry.setUser()`等で利用者を識別する情報を付与する場合は、
  このファイルを更新し、削除導線の要否を再検討する。
